Expand description

A picture being drawn a transaction at a time.

A transaction is drawn by Writer::set, once per block in its color, and closed by Writer::end_transaction; every bin of those makes a row, and every TILE rows make a band that goes out to the encoder.

Fields§

§codec: Box<Codec>

Boxed, and set up only once it is in the box. The encoder keeps pointers into itself — the tile coder’s cp is the address of the codec’s own coding parameters — so an encoder that has been started and is then moved is an encoder reading whatever now lives where it used to be. A box is an address that does not move when this struct does, and putting it there before [Codec::setup_encoder] is what makes the pointers it takes stay true. Left on the stack it fails the way that costs the most to find: the debug build works.

§stream: Stream§image: Box<opj_image>

The encoder was set up against this and reads it as it goes, so it outlives the setup call rather than being a local of it.

§width: usize

Columns, i.e. how many block ids the picture has room for.

§height: usize

Rows, as promised to the encoder before the first sample.

§bin: usize

Transactions to a row. One is a row each, which is the plain picture.

§stride: usize

Bytes a packed row: the distance from one row of band to the next.

§across: usize

Tiles across the picture, which is also the stride of a tile index.

§band: Vec<u8>

Up to TILE rows, packed eight pixels to the byte. Zero outside ..dirty of each row at all times, which is the invariant that lets Writer::flush_band clear only a prefix of each.

§dirty: usize§filled: usize

Rows finished in the band so far, always below TILE.

§pending: usize

Transactions drawn into the row being built, always below bin.

§rows: usize

Rows finished in the picture so far, at most height.

§bands: usize

Bands sent, which is the tile row the next one will be.

§escaped: Option<usize>

The first block id seen that the picture has no column for, if any.

pub fn new(path: &str, width: usize, height: usize, bin: usize) -> Result<Self>

Open path for a picture width columns by height rows, with bin transactions to the row, and start the codestream.

Both dimensions are final here: see the module docs for why a JPEG 2000 cannot be told either of them later.

Source

pub fn set(&mut self, block: usize)

Ink the pixel for block in the row being built.

A block the picture has no column for is remembered rather than reported: this runs inside the store’s walk over the color’s terms, which has nowhere to put an error. Writer::end_transaction raises it, naming the first one — the first is the informative one, since the rest are whatever the run went on to see afterwards.

Source

pub fn end_transaction(&mut self) -> Result<()>

Finish one transaction, closing the row if it completes a bin.

Source

fn end_row(&mut self) -> Result<()>

Close the row being built and start the next one, sending the band if that filled it.

Source

fn flush_band(&mut self) -> Result<()>

Hand the finished band to the encoder, a tile at a time, and clear it.

The band is as tall as the tile row it stands for — full bands are TILE rows and the last one is whatever is left of the height, which Writer::finish arranges by padding — so its rows are exactly the samples the encoder is expecting for these tile indices.

Source

fn tile_bytes(&self, x0: usize, x1: usize, rows: usize) -> Vec<u8> ⓘ

One tile of the band as the samples the encoder wants: row-major, a byte a sample, [x0, x1) of each of the band’s first rows rows.

x0 is a multiple of TILE and so of 8, which is what lets a whole packed byte become eight samples in one copy; only the far edge of the picture, where x1 need not be a multiple of anything, is trimmed.

Source

pub fn dimensions(&self) -> (usize, usize)

(columns, rows) as the picture was opened for, which is what it will be however many records turn up.

Source

pub fn finish(self) -> Result<()>

Close the picture: finish the row in hand, pad out to the promised height, send what is left of the band, and close the codestream.
