pub fn eight_digits(chunk: u64) -> u64
Expand description

The value of eight ASCII digits packed into chunk, the first digit in the lowest-addressed byte. Callers get there with u64::from_le_bytes, which keeps this correct on a big-endian target too.

Three rounds of divide-and-conquer, each folding neighbouring lanes into lanes twice as wide. The multiplier in each round is two set fields — 1 and the power of ten that weights the lane above — so one multiply does the whole hi * 10^k + lo for every pair at once, and the shift-and-mask picks the combined halves back out:

 '1' '2' '3' '4' '5' '6' '7' '8'   eight bytes
  \_/     \_/     \_/     \_/      x 2561      = 10<<8   | 1
  12      34      56      78       four u16
    \____/          \____/         x 6553601   = 100<<16 | 1
    1234            5678           two u32
       \____________/              x 42949672960001 = 10000<<32 | 1
          12345678                 one u64

No lane can carry into its neighbour on the way: the largest intermediate any round produces is 99, 9999, 99999999, each one inside its lane.

The caller is responsible for the bytes actually being digits — feeding this anything else yields a meaningless number rather than an error.
