1//! # A webgraph, drawn as a JPEG 2000
2//!
3//! Reads a BvGraph by basename, treats it as a forest, and writes a **lossless**
4//! JPEG 2000 in which every node is one pixel, placed where the non-layered tidy
5//! trees algorithm (van der Ploeg 2014) puts it.  How the graph becomes a tree,
6//! where its roots come from, and what the layout is asked for are all in
7//! [`forest`]; this file is only about turning coordinates into a codestream.
8//!
9//! ```text
10//! tree-jp2 <graph-basename> -o <file> [--zoom <n>]
11//! ```
12//!
13//! # A pixel per node, and not a pixel more
14//!
15//! The layout's units are nodes, so a pixel grid is a matter of picking how many
16//! pixels a unit is worth — and the answer is different on the two axes, because
17//! the layout treats them differently:
18//!
19//! - Along **depth** nothing separates one level from the next: a child's near
20//!   edge is its parent's far edge, so level `d` sits at `x = d` and
21//!   [`DEPTH_PX`] of 1 makes column `d` that level, exactly.
22//! - Along **breadth** every node carries [`forest::SUBTREE_MARGIN`], so two
23//!   nodes at the same depth have centres at least two units apart — one for the
24//!   node, one for the clear space beside it.  [`BREADTH_PX`] of 1/2 spends a
25//!   pixel on the pair, which is what closes up the blank row that would
26//!   otherwise sit under every node.
27//!
28//! Together they are the tightest grid the drawing fits in: every node lands on
29//! its own pixel, no pixel is wasted on the margins, and a picture of `n` nodes
30//! is about as many pixels.  Since the separation is a lower bound rather than
31//! an equality — the algorithm pushes subtrees further apart when their shapes
32//! demand it — the grid has white in it wherever the tree does, which is the
33//! shape one wants to see.  Nothing *guarantees* two nodes cannot round into one
34//! pixel, so [`Picture::collisions`] counts the ones that did and the run says
35//! so rather than quietly drawing `n - 1` nodes.
36//!
37//! `--zoom n` then repeats every pixel `n` times on each axis, for the small
38//! graphs where a picture a few pixels across is not a picture.  It is a whole
39//! number because a raster has no way to be given a fractional one.
40//!
41//! The picture is one 8-bit greyscale component in three tones: leaves are
42//! [`LEAF_INK`] against [`INNER_INK`] nodes on [`PAPER`], the same three the
43//! windowed viewer draws.
44//!
45//! # Why lossless, and what that costs
46//!
47//! A lossy JPEG 2000 would be smaller and would be the wrong picture: a node is
48//! one pixel, so the difference between a node and no node is a single sample,
49//! and that is exactly what a quantiser spends first.  So the encoder is set up
50//! for the reversible path — the 5/3 integer wavelet, no quantisation, one
51//! quality layer at no rate cap — and the bytes that go in are the bytes that
52//! come back.  The `round_trips_losslessly` test asserts that against the
53//! decoder rather than trusting the setting.
54//!
55//! What that buys over a raw raster is the compression a netpbm has no way to
56//! express.  These pictures are nearly all paper, and the wavelet plus EBCOT
57//! charges almost nothing for it: `cnr-2000`, 325 557 nodes on a 37-by-218 886
58//! grid, comes to 1.1 MB against the 8.1 MB the same pixels are as a `P5`.  And
59//! unlike `gzip` over a raster, the result is still an image every tool can
60//! open, and one that can be decoded at a reduced resolution — [`RESOLUTIONS`]
61//! of them — without reading it whole.
62//!
63//! What it costs is time.  A raster writer is a memcpy; this runs a wavelet and
64//! an arithmetic coder over every sample, paper included.
65//!
66//! # Why this streams, and why it wants a file
67//!
68//! The whole raster is `width * height` and the nodes are only `n`, so the
69//! picture is held as one `(row, column, ink)` per node — twelve bytes, against
70//! a byte for every pixel of a picture that is mostly white.  Sorting that list
71//! puts the nodes in the order the tiles are written, so the raster is built one
72//! [`TILE`]-square tile at a time and never exists whole: the memory here is one
73//! tile's worth however big the picture is, which is what lets a drawing far
74//! past the size of memory be written at all.
75//!
76//! The codestream is not written straight through, though — the encoder goes
77//! back to stamp lengths into markers it has already emitted — so the output has
78//! to be a file it can seek in, and `-o` is required rather than defaulting to
79//! standard output the way a netpbm writer could.
80

95/// Pixels per node unit along the depth axis: a column is a level.
96const DEPTH_PX: f64 = 1.0;
97
98/// Pixels per node unit along the breadth axis: a row is a node and the margin
99/// beside it.  See the module docs for why the two axes differ.
100const BREADTH_PX: f64 = 0.5;
101
102/// The three tones, matching the viewer's `#000000`, `#808080`, `#ffffff`.
103const INNER_INK: u8 = 0x00;
104const LEAF_INK: u8 = 0x80;
105const PAPER: u8 = 0xff;
106
107/// How many pixels a node pixel becomes on a side, when the caller does not say.
108const DEFAULT_ZOOM: usize = 1;
109
110/// The side of the square the picture is written in.  This is the working set:
111/// a tile is built whole in memory and handed to the encoder, so the number is a
112/// trade of memory against how much context the wavelet has to compress with,
113/// and 1024 is a mebibyte a tile.
114const TILE: usize = 1024;
115
116/// Wavelet decomposition levels.  Six is the encoder's own default, and it is
117/// also what lets a viewer open one of these at 1/32 scale without decoding the
118/// full-size picture.
119const RESOLUTIONS: i32 = 6;

121const USAGE: &str = "usage: tree-jp2 <graph-basename> -o <file> [--zoom <n>]\n\

124/// The drawing as pixels: what row and column each node landed on, and how big
125/// the grid holding them is.
126struct Picture {
127    /// Columns and rows, in node pixels — before any `--zoom`.
128    width: usize,
129    height: usize,
130    /// One entry per drawn node, sorted by `(row, column)`, with the darker ink
131    /// first so that a node with children wins a pixel a leaf also wants.
132    dots: Vec<(u32, u32, u8)>,
133    /// Nodes that landed on a pixel another node already had.  Zero on every
134    /// forest seen so far; see the module docs for why it is counted anyway.
135    collisions: usize,
136}

138/// Puts every node of a laid-out arena on a pixel.
139fn plot(arena: &Arena) -> Result<Picture, String> {
140    // The bounding box is measured over the nodes actually drawn rather than
141    // taken from the layout's normalization, because the node standing for
142    // nothing is in the arena and is not in the picture.
143    let (mut min_x, mut min_y) = (f64::INFINITY, f64::INFINITY);
144    let (mut max_x, mut max_y) = (f64::NEG_INFINITY, f64::NEG_INFINITY);
145    let mut drawn = 0usize;
146
147    for node in arena.iter() {
148        if node.isdummy {
149            continue;
150        }
151        drawn += 1;
152        min_x = min_x.min(node.x);
153        min_y = min_y.min(node.y);
154        max_x = max_x.max(node.x + node.w);
155        max_y = max_y.max(node.y + node.h);
156    }
157
158    if drawn == 0 {
159        return Err("nothing to draw".to_string());
160    }
161
162    // Rounded up, so that the last column and row are whole ones: the grid is
163    // the smallest that has room for every box the layout placed.
164    let width = (((max_x - min_x) * DEPTH_PX).ceil() as usize).max(1);
165    let height = (((max_y - min_y) * BREADTH_PX).ceil() as usize).max(1);
166
167    // A coordinate is a `u32` so that the list costs twelve bytes a node rather
168    // than twenty-four; 4 294 967 295 columns is past what any of this could
169    // draw, and past it the message should be about the picture, not a panic.
170    if width.max(height) > u32::MAX as usize {
171        return Err(format!(
172            "the drawing is {width} by {height} pixels, which is more than this can raster"
173        ));
174    }
175
176    let mut dots = Vec::with_capacity(drawn);
177
178    for node in arena.iter() {
179        if node.isdummy {
180            continue;
181        }
182        // The centre of the box rather than its corner, so that a node whose
183        // breadth coordinate is a half — every parent centred over its children
184        // has one — falls in the row it looks like it is in.  `min` guards the
185        // far edge, where a centre can round onto the column past the last.
186        let col = (((node.x + node.w / 2.0 - min_x) * DEPTH_PX) as usize).min(width - 1);
187        let row = (((node.y + node.h / 2.0 - min_y) * BREADTH_PX) as usize).min(height - 1);
188        let ink = if node.children().is_empty() {
189            LEAF_INK
190        } else {
191            INNER_INK
192        };
193        dots.push((row as u32, col as u32, ink));
194    }
195
196    // Sorting by the tuple sorts by row, then column, then ink -- and `INNER_INK`
197    // is the smaller number, which is what makes the first of two nodes on one
198    // pixel the darker one.
199    dots.sort_unstable();
200    let before = dots.len();
201    dots.dedup_by_key(|&mut (row, col, _)| (row, col));
202
203    Ok(Picture {
204        width,
205        height,
206        collisions: before - dots.len(),
207        dots,
208    })
209}

211/// One tile of the zoomed picture, as the bytes the encoder wants: row-major,
212/// a byte a pixel, clipped to the image at the far edge.
213///
214/// `(x0, y0)` is the tile's corner in zoomed pixels and `(x1, y1)` one past its
215/// far corner.  The dots are looked up rather than walked because a source row
216/// covers `zoom` rows of the picture and so can fall in two tiles.
217fn tile_bytes(
218    picture: &Picture,
219    zoom: usize,
220    (x0, y0): (usize, usize),
221    (x1, y1): (usize, usize),
222) -> Vec<u8> {
223    let (w, h) = (x1 - x0, y1 - y0);
224    let mut tile = vec![PAPER; w * h];
225
226    // The source rows any of this tile's rows came from.  Both ends are rows
227    // that exist, since the tile itself is inside the picture.
228    let (lo, hi) = ((y0 / zoom) as u32, ((y1 - 1) / zoom) as u32);
229    let from = picture.dots.partition_point(|&(row, ..)| row < lo);
230    let to = picture.dots.partition_point(|&(row, ..)| row <= hi);
231
232    for &(row, col, ink) in &picture.dots[from..to] {
233        // The block of zoomed pixels this node covers, clipped to the tile.
234        let (bx0, bx1) = (col as usize * zoom, (col as usize + 1) * zoom);
235        let (by0, by1) = (row as usize * zoom, (row as usize + 1) * zoom);
236        let (bx0, bx1) = (bx0.max(x0), bx1.min(x1));
237        let (by0, by1) = (by0.max(y0), by1.min(y1));
238        if bx0 >= bx1 {
239            continue;
240        }
241        for y in by0..by1 {
242            let at = (y - y0) * w + (bx0 - x0);
243            tile[at..at + (bx1 - bx0)].fill(ink);
244        }
245    }
246
247    tile
248}

250/// Writes the picture to `path` as a lossless JPEG 2000, one tile at a time.
251fn write_jp2(picture: &Picture, path: &str, zoom: usize) -> Result<(), String> {
252    let width = picture.width * zoom;
253    let height = picture.height * zoom;
254
255    let comp = opj_image_comptparm {
256        dx: 1,
257        dy: 1,
258        w: width as u32,
259        h: height as u32,
260        x0: 0,
261        y0: 0,
262        prec: 8,
263        bpp: 8,
264        sgnd: 0,
265    };
266    // `tile_create` rather than `create`: it describes the picture without
267    // allocating a sample for every pixel of it, which is the whole point of
268    // handing the encoder one tile at a time.  The extent is not in the
269    // component parameters, so it is set here.
270    let mut image =
271        opj_image::tile_create(&[comp], OPJ_CLRSPC_GRAY).ok_or("could not describe the image")?;
272    image.x1 = width as u32;
273    image.y1 = height as u32;
274
275    let mut params = opj_cparameters_t::default();
276    params.tile_size_on = 1;
277    params.cp_tdx = TILE as i32;
278    params.cp_tdy = TILE as i32;
279    params.numresolution = RESOLUTIONS;
280    params.prog_order = OPJ_LRCP;
281    // Lossless: the reversible 5/3 wavelet, and one quality layer whose rate is
282    // 0 — the encoder's spelling of "do not throw anything away".
283    params.irreversible = 0;
284    params.tcp_numlayers = 1;
285    params.tcp_rates[0] = 0.0;
286    params.cp_disto_alloc = 1;
287
288    let mut codec = Codec::new_encoder(OPJ_CODEC_JP2).ok_or("could not open a JPEG 2000 encoder")?;
289    // The encoder seeks back over what it has written, so this is a file rather
290    // than the caller's choice of sink.
291    let mut stream =
292        Stream::new_file(path, 1 << 20, false).map_err(|e| format!("{path}: {e}"))?;
293
294    if codec.setup_encoder(&mut params, &mut image) == 0 {
295        return Err(format!("{path}: the encoder would not take these settings"));
296    }
297    if codec.start_compress(&mut image, &mut stream) == 0 {
298        return Err(format!("{path}: could not start the codestream"));
299    }
300
301    // Tiles go out in index order across and then down, which is the order the
302    // encoder counts them in and the only one it accepts.
303    let across = width.div_ceil(TILE);
304    let down = height.div_ceil(TILE);
305
306    for ty in 0..down {
307        let (y0, y1) = (ty * TILE, ((ty + 1) * TILE).min(height));
308        for tx in 0..across {
309            let (x0, x1) = (tx * TILE, ((tx + 1) * TILE).min(width));
310            let bytes = tile_bytes(picture, zoom, (x0, y0), (x1, y1));
311            let index = (ty * across + tx) as u32;
312            if codec.write_tile(index, &bytes, &mut stream) == 0 {
313                return Err(format!("{path}: could not write tile {index}"));
314            }
315        }
316    }
317
318    if codec.end_compress(&mut stream) == 0 {
319        return Err(format!("{path}: could not close the codestream"));
320    }
321
322    Ok(())
323}

325/// `n` bytes as something a person can read at a glance.
326fn human(bytes: u64) -> String {
327    const UNITS: [&str; 5] = ["B", "kB", "MB", "GB", "TB"];
328    let mut size = bytes as f64;
329    let mut unit = 0;
330    while size >= 1000.0 && unit + 1 < UNITS.len() {
331        size /= 1000.0;
332        unit += 1;
333    }
334    if unit == 0 {
335        format!("{bytes} B")
336    } else {
337        format!("{size:.1} {}", UNITS[unit])
338    }
339}

341fn run() -> Result<(), String> {
342    let argv: Vec<String> = env::args().skip(1).collect();
343
344    let mut basenames: Vec<&str> = Vec::new();
345    let mut out_path: Option<&str> = None;
346    let mut zoom = DEFAULT_ZOOM;
347    let mut roots: Vec<usize> = Vec::new();
348    let mut prune = forest::Prune::default();
349
350    let mut i = 0;
351    while i < argv.len() {
352        match argv[i].as_str() {
353            "-o" | "--out" => {
354                i += 1;
355                out_path = Some(argv.get(i).ok_or_else(|| format!("-o wants a file\n{USAGE}"))?);
356            }
357            "--zoom" => {
358                i += 1;
359                let v = argv.get(i).ok_or_else(|| format!("--zoom wants a number\n{USAGE}"))?;
360                zoom = v.parse::<usize>().map_err(|_| format!("--zoom {v}: not a number"))?;
361                if zoom == 0 {
362                    return Err("--zoom 0: a node is at least one pixel".to_string());
363                }
364            }
365            "--root" => {
366                i += 1;
367                let v = argv.get(i).ok_or_else(|| format!("--root wants a node id\n{USAGE}"))?;
368                for part in v.split(',') {
369                    roots.push(
370                        part.parse::<usize>()
371                            .map_err(|_| format!("--root {part}: not a node id"))?,
372                    );
373                }
374            }
375            "--depth" => {
376                i += 1;
377                let v = argv.get(i).ok_or_else(|| format!("--depth wants a number\n{USAGE}"))?;
378                prune.depth =
379                    Some(v.parse::<usize>().map_err(|_| format!("--depth {v}: not a number"))?);
380            }
381            "--max-nodes" => {
382                i += 1;
383                let v =
384                    argv.get(i).ok_or_else(|| format!("--max-nodes wants a number\n{USAGE}"))?;
385                prune.max_nodes = v
386                    .parse::<usize>()
387                    .ok()
388                    .filter(|&n| n > 0)
389                    .ok_or_else(|| format!("--max-nodes {v}: wants a positive number"))?;
390            }
391            "--fanout" => {
392                i += 1;
393                let v = argv.get(i).ok_or_else(|| format!("--fanout wants a number\n{USAGE}"))?;
394                prune.fanout = Some(
395                    v.parse::<usize>()
396                        .ok()
397                        .filter(|&n| n > 0)
398                        .ok_or_else(|| format!("--fanout {v}: wants a positive number"))?,
399                );
400            }
401            "-h" | "--help" => return Err(USAGE.to_string()),
402            other if other.starts_with('-') => return Err(format!("unknown flag {other}\n{USAGE}")),
403            other => basenames.push(other),
404        }
405        i += 1;
406    }
407
408    let [graph_name] = basenames.as_slice() else {
409        return Err(format!(
410            "expected one graph basename, got {}\n{USAGE}",
411            basenames.len()
412        ));
413    };
414
415    // See the module docs: the codestream is written with backward seeks, so
416    // there is no standard-output form of this to fall back to.
417    let Some(out_path) = out_path else {
418        return Err(format!(
419            "-o is required: a JPEG 2000 is written by seeking back over it, \
420             which a pipe cannot do\n{USAGE}"
421        ));
422    };
423
424    // `load` answers with an `anyhow::Error`, which is not this crate's to name;
425    // it is a `Display` all the same, and that is all a message needs.
426    let graph = BvGraph::with_basename(graph_name)
427        .load()
428        .map_err(|e| format!("{graph_name}: {e:#}"))?;
429
430    // Named roots draw those subtrees, pruned as asked; no roots is the whole
431    // graph read as a forest, exactly as before the flags existed.
432    let (root, arena) = if roots.is_empty() {
433        let mut arena = Arena::with_capacity(graph.num_nodes() + 1);
434        let built = forest::build(&graph, &mut arena)?;
435        eprintln!("{}", built.summary(graph.num_nodes()));
436        (built.root, arena)
437    } else {
438        let mut arena = Arena::new();
439        let sampled = forest::build_rooted(&graph, &mut arena, &roots, &prune)?;
440        eprintln!("{}", sampled.summary());
441        (sampled.root, arena)
442    };
443
444    let arena = forest::lay_out(arena, root);
445    let picture = plot(&arena)?;
446
447    let (width, height) = (picture.width * zoom, picture.height * zoom);
448    eprintln!(
449        "{width} by {height} pixels, in {} tile(s) of {TILE}",
450        width.div_ceil(TILE) * height.div_ceil(TILE)
451    );
452
453    if picture.collisions > 0 {
454        eprintln!(
455            "{} node(s) share a pixel with another and are not drawn separately; \
456             --zoom does not help, the grid is what it is",
457            picture.collisions
458        );
459    }
460
461    write_jp2(&picture, out_path, zoom)?;
462
463    let size = std::fs::metadata(out_path)
464        .map(|m| m.len())
465        .map_err(|e| format!("{out_path}: {e}"))?;
466    eprintln!("{} pixels drawn, {} written", picture.dots.len(), human(size));
467    Ok(())
468}

470fn main() -> ExitCode {
471    match run() {
472        Ok(()) => ExitCode::SUCCESS,
473        Err(message) => {
474            eprintln!("{message}");
475            ExitCode::FAILURE
476        }
477    }
478}

509    /// The grid a picture is drawn on, as one string a row at a time: `#` for a
510    /// node with children, `+` for a leaf, `.` for paper.
511    fn render(picture: &Picture) -> String {
512        let mut grid = vec![vec!['.'; picture.width]; picture.height];
513        for &(row, col, ink) in &picture.dots {
514            grid[row as usize][col as usize] = if ink == LEAF_INK { '+' } else { '#' };
515        }
516        grid.into_iter()
517            .map(|r| r.into_iter().collect::<String>())
518            .collect::<Vec<_>>()
519            .join("\n")
520    }

522    /// The same, read back out of a written file: `width * height` samples in
523    /// row-major order, which is what the encoder was handed if nothing was lost.
524    fn decode(path: &str) -> (usize, usize, Vec<u8>) {
525        let mut params = opj_dparameters_t::default();
526        let mut codec = Codec::new_decoder(OPJ_CODEC_JP2).unwrap();
527        assert!(codec.setup_decoder(&mut params) != 0);
528
529        let mut stream = Stream::new_file(path, 1 << 20, true).unwrap();
530        let mut image = codec.read_header(&mut stream).expect("a JP2 header");
531        assert!(codec.decode(&mut stream, &mut image) != 0);
532        assert!(codec.end_decompress(&mut stream) != 0);
533
534        let (w, h) = (image.x1 as usize, image.y1 as usize);
535        let comps = image.comps().unwrap();
536        assert_eq!(comps.len(), 1, "one greyscale component");
537        let samples = comps[0].data().unwrap().iter().map(|&s| s as u8).collect();
538
539        (w, h, samples)
540    }

549    /// The picture as bytes, straight from the dots: what the file has to decode
550    /// back to, pixel for pixel.
551    fn expected(picture: &Picture, zoom: usize) -> Vec<u8> {
552        let (w, h) = (picture.width * zoom, picture.height * zoom);
553        let mut want = vec![PAPER; w * h];
554        for &(row, col, ink) in &picture.dots {
555            for y in row as usize * zoom..(row as usize + 1) * zoom {
556                let at = y * w + col as usize * zoom;
557                want[at..at + zoom].fill(ink);
558            }

642    /// The claim the whole file rests on: what the encoder was handed is what the
643    /// decoder gives back, sample for sample.  Nothing in the settings *says*
644    /// lossless out loud, so it is asserted rather than assumed.
645    #[test]
646    fn round_trips_losslessly() {
647        let picture = everything();
648        let path = scratch("lossless");
649
650        write_jp2(&picture, &path, 1).unwrap();
651
652        let (w, h, samples) = decode(&path);
653        assert_eq!((w, h), (picture.width, picture.height));
654        assert_eq!(samples, expected(&picture, 1), "every sample survived");
655
656        // And the three tones are still three distinct tones, not three tones
657        // that a quantiser has quietly pulled together.
658        let mut tones: Vec<u8> = samples.clone();
659        tones.sort_unstable();
660        tones.dedup();
661        assert_eq!(tones, [INNER_INK, LEAF_INK, PAPER]);
662
663        std::fs::remove_file(&path).ok();
664    }

666    /// A picture wider and taller than one tile, so that the tile loop runs more
667    /// than once on each axis and the seams have to line up.
668    #[test]
669    fn a_picture_of_many_tiles_round_trips() {
670        // A chain of `n` nodes is `n` levels deep and one row tall, so the depth
671        // axis alone would never make a second tile row.  Zoom makes both axes
672        // bigger at once.
673        let arcs: Vec<(usize, usize)> = (0..TILE + 200).map(|i| (i, i + 1)).collect();
674        let g = forest::graph_of(arcs.len() + 1, &arcs);
675
676        let mut arena = Arena::with_capacity(arcs.len() + 2);
677        let built = forest::build(&g, &mut arena).unwrap();
678        let arena = forest::lay_out(arena, built.root);
679        let picture = plot(&arena).unwrap();
680
681        let zoom = 2;
682        let (w, h) = (picture.width * zoom, picture.height * zoom);
683        assert!(w > TILE, "more than one tile across, so the seam is exercised");
684
685        let path = scratch("tiles");
686        write_jp2(&picture, &path, zoom).unwrap();
687
688        let (dw, dh, samples) = decode(&path);
689        assert_eq!((dw, dh), (w, h));
690        assert_eq!(samples, expected(&picture, zoom));
691
692        std::fs::remove_file(&path).ok();
693    }
