1//! # Colors as a picture
2//!
3//! The text output names every block in every color, which on a real run is
4//! tens of gigabytes of `(block . 1)` pairs.  The same answer drawn instead of
5//! spelled: one **row** per transaction, in the order the transactions arrive,
6//! one **column** per block id, counting up from 0, and a black pixel wherever
7//! that block is in that transaction's color.  A color of a thousand blocks is a
8//! thousand bits rather than fourteen thousand bytes, and how far back a
9//! transaction's coins reach is something you can then look at.
10//!
11//! What the picture drops is the coefficients.  For the unweighted backends
12//! there is nothing to drop — every coefficient is 1, so the color *is* its set
13//! of blocks and the bitmap is the whole answer.  Under `--weighted` a pixel
14//! says only that some of the transaction's value came from that block, not how
15//! much; a weight too small to print as anything but `0.000000` is a black pixel
16//! like any other, which is one thing the picture shows better than the text.
17//!
18//! ## Two formats, and which one is smaller
19//!
20//! [`Format::Pbm`] is netpbm's binary bitmap, `P4`: a short text header, then the
21//! rows packed eight pixels to the byte with the leftmost pixel in the *most*
22//! significant bit and each row padded out to a whole byte.  A 1 bit is black,
23//! which is what makes "the ones in the output" and "the black pixels" the same
24//! statement.  Every image tool reads it.  A row costs `width / 8` bytes and
25//! nothing else: the same whether it is empty or solid.
26//!
27//! [`Format::Svg`] draws the same rows as horizontal strokes, one per *run* of
28//! adjacent blocks.  A row then costs about [`SVG_BYTES_PER_RUN`] bytes per run
29//! and nothing at all for the white between them, so the two formats scale
30//! against different things:
31//!
32//! ```text
33//!     SVG is smaller  <=>  runs per row  <  width / 56
34//! ```
35//!
36//! Which side of that a real chain falls on is a question about the records
37//! rather than about the formats, so `--stats` measures it and says what the
38//! other format would have cost — see [`Writer::runs`].  Colors that reach back
39//! in a few long stretches are a handful of runs however wide the image, and
40//! drawing those is far cheaper than packing rows that are mostly white; on
41//! synthetic runs here the same records came out
42//!
43//! ```text
44//!     width   runs/row     PBM        SVG    smaller by
45//!     50,000       6.3   625 MB     5.2 MB       120x
46//!     10,000     176.0   125 MB   112.4 MB       1.11x
47//!      5,000      48.1   125 MB    60.4 MB       2.07x
48//! ```
49//!
50//! and it takes a color shot through with gaps — a run every fifty-six columns,
51//! all the way across — before the bitmap starts to win.
52//!
53//! What the vector picture gives up is that it is one enormous `<path>`.  Every
54//! image tool reads a `P4`; an SVG of a million rows is a file a browser has to
55//! be willing to parse before it will show anything.
56//!
57//! Neither is compressed, and both compress well; the bitmap of a 200,000-record
58//! run goes from 125 MB to 8.8 MB through `gzip` and 6.5 MB through `zstd`.  If
59//! the output is only ever going to be read back by a program, that is a bigger
60//! win than the choice of format, and it composes with either.
61//!
62//! ## Folding transactions together
63//!
64//! A row per transaction is a row per record, and a real run has more records
65//! than any screen has pixels — a million rows is already a picture nothing will
66//! show you whole.  So a row may stand for more than one transaction:
67//! [`Writer::new`]'s `bin` is how many consecutive transactions share a row, and
68//! the row they share is the union of their colors, black where *any* of them
69//! reaches that block.  Union is what the driver is computing anyway, so a
70//! binned picture is the same picture at a coarser scale rather than a sampled
71//! or averaged one, and nothing that was black can go white.  The last bin is
72//! whatever is left over, and it is written like any other.
73//!
74//! ## Why the header is padded, and why this wants a file
75//!
76//! Both formats put the height in front of the picture, and the height is the
77//! number of transactions — not known until the input has ended, by which time
78//! the picture is written and gigabytes long.  So the header is written with a
79//! placeholder and padded out to a length that cannot change, and
80//! [`Writer::finish`] seeks back and stamps the real number into the hole.  A
81//! `usize` never needs more than 20 digits, so what each format pads *with* is
82//! the only difference: netpbm lets any run of whitespace separate two header
83//! tokens, and XML lets any run of it separate two attributes.
84//!
85//! That seek is why this writes to a file rather than to stdout: a pipe cannot
86//! be rewound.  The width has no such escape — it fixes the distance from one
87//! row to the next, so it cannot be discovered along the way the height can, and
88//! has to be settled before the first row is written.  `--blocks` says it
89//! outright; without it the driver counts the blocks first, by reading the
90//! records twice — see `main`'s `survey`.
91
92use std::io::{self, BufWriter, Seek, SeekFrom, Write};

94/// Blanks reserved for the row count in a `P4` header.
95///
96/// `usize::MAX` is 20 digits, so a field this wide fits any number of rows a run
97/// could produce and the header's length is a function of the width alone.  That
98/// is the whole trick — see the module docs.
99const HEIGHT_DIGITS: usize = 20;
100
101/// Which of the two pictures to draw.  The module docs say when each is smaller.
102#[derive(Clone, Copy, PartialEq, Eq, Debug)]
103pub enum Format {
104    /// Netpbm's binary bitmap: `width / 8` bytes a row, whatever is in it.
105    Pbm,
106    /// One stroke per run of adjacent blocks: nothing for the white.
107    Svg,
108}
109
110/// What one run costs as a stroke, near enough for the note `--stats` prints
111/// about the format that was not chosen.
112///
113/// Measured rather than counted up from the grammar: `m-4930 1h6` is ten bytes
114/// and a run at the start of a row is six, and across four synthetic runs of
115/// very different shapes the mean came out between 6.3 and 8.3.  It stays that
116/// short however big the picture gets because every move but the first says how
117/// far the pen went rather than where it landed, and a step is a few digits even
118/// when the coordinates are seven.
119const SVG_BYTES_PER_RUN: usize = 7;
120
121impl Format {
122    /// Roughly what a row of `runs` runs costs in this format.
123    fn row_bytes(self, width: usize, runs: usize) -> usize {
124        match self {
125            Format::Pbm => width.div_ceil(8),
126            Format::Svg => SVG_BYTES_PER_RUN * runs,
127        }
128    }
129}

131/// `P4`, `width` columns, `rows` rows, with the row count right-aligned in its
132/// fixed-width field.
133fn pbm_header(width: usize, rows: usize) -> String {
134    format!("P4\n{} {:>field$}\n", width, rows, field = HEIGHT_DIGITS)
135}

137/// The opening of an SVG `width` by `rows`, padded to a length that does not
138/// depend on `rows`.
139///
140/// The padding is spaces before the tag's `>`, which is whitespace between
141/// attributes as far as any XML parser is concerned — nothing has to be told
142/// about it, and unlike padding a number it cannot change what the number means.
143///
144/// Rows are strokes rather than rectangles, which is what keeps a run down to
145/// about twelve bytes: a stroke is a move and a horizontal line, where a
146/// rectangle is four numbers and a tag.  `stroke-width` 1 on a path shifted down
147/// half a pixel puts the stroke exactly over the row, so every coordinate in the
148/// path stays a whole number.
149fn svg_header(width: usize, rows: usize) -> String {
150    let tag = |height: usize| {
151        format!(
152            "<svg xmlns=\"http://www.w3.org/2000/svg\" width=\"{0}\" height=\"{1}\" \
153             viewBox=\"0 0 {0} {1}\" shape-rendering=\"crispEdges\"",
154            width, height
155        )
156    };
157    let mut open = tag(rows);
158    // Every height that could replace this one is at most as long as the widest
159    // a `usize` gets, so padding to that is padding to a fixed length.
160    let padding = tag(usize::MAX).len() - open.len();
161    open.extend(std::iter::repeat_n(' ', padding));
162    format!(
163        "{}><rect width=\"100%\" height=\"100%\" fill=\"#fff\"/>\
164         <path fill=\"none\" stroke=\"#000\" stroke-width=\"1\" \
165         transform=\"translate(0,.5)\" d=\"",
166        open
167    )
168}
169
170/// What closes an SVG, once the last stroke is in.
171const SVG_TAIL: &str = "\"/></svg>\n";
172
173/// Visit the maximal runs of black pixels in `row` as `(start, length)`.
174///
175/// Uniform bytes are stepped over eight pixels at a time, which is what makes
176/// this cheap on the rows that matter: a color that reaches back a long way is
177/// mostly solid `0xff` and empty `0x00`, and only the ends of its runs cost a
178/// look at individual bits.
179fn for_each_run(row: &[u8], mut visit: impl FnMut(usize, usize)) {
180    let bits = row.len() * 8;
181    let black = |x: usize| row[x / 8] & (0x80 >> (x % 8)) != 0;
182
183    // The next pixel at or after `from` that is black, or is not.
184    let find = |mut x: usize, want: bool| {
185        let skip = if want { 0x00 } else { 0xff };
186        while x < bits {
187            if x.is_multiple_of(8) && row[x / 8] == skip {
188                x += 8;
189            } else if black(x) == want {
190                return x;
191            } else {
192                x += 1;
193            }
194        }
195        bits
196    };
197
198    let mut x = find(0, true);
199    while x < bits {
200        let end = find(x, false);
201        visit(x, end - x);
202        x = find(end, true);
203    }
204}

206/// A bitmap being written a row at a time.
207///
208/// A transaction is drawn by [`Writer::set`], once per block in its color, and
209/// closed by [`Writer::end_transaction`]; every `bin` of those makes a row.  The
210/// rows are streamed out as they are finished, so the memory here is one row's
211/// worth however tall the image gets.
212pub struct Writer<W: Write + Seek> {
213    out: BufWriter<W>,
214    /// Columns, i.e. how many block ids the image has room for.
215    width: usize,
216    /// Transactions to a row.  One is a row each, which is the plain picture.
217    bin: usize,
218    /// The row being built, eight pixels to the byte and rounded up to a whole
219    /// one.  Zero outside `..dirty` at all times, which is the invariant that
220    /// lets [`Writer::flush_row`] clear only a prefix.
221    row: Vec<u8>,
222    dirty: usize,
223    /// Transactions drawn into the row so far, always below `bin`.
224    pending: usize,
225    rows: usize,
226    /// The first block id seen that the image has no column for, if any.
227    escaped: Option<usize>,
228    /// Length of the placeholder header, which is also where the picture starts.
229    header_len: usize,
230    format: Format,
231    /// Where the SVG path's pen is, once it has been put down.  Every move after
232    /// the first is relative to it, which is what keeps the numbers short in an
233    /// image whose coordinates run to seven digits.
234    pen: Option<(usize, usize)>,
235    /// The strokes of one row, built up before going out in a single write.
236    /// Reused across rows, like the driver's line buffer.
237    strokes: Vec<u8>,
238    /// Runs counted so far, and whether to bother counting them.  Only `--stats`
239    /// wants this, and for [`Format::Pbm`] counting means a scan of the row that
240    /// writing it does not otherwise need.
241    runs: u64,
242    measure: bool,
243}
244
245impl<W: Write + Seek> Writer<W> {
246    /// Start a picture `width` columns wide with `bin` transactions to the row,
247    /// writing the placeholder header.
248    pub fn new(
249        inner: W,
250        format: Format,
251        width: usize,
252        bin: usize,
253        measure: bool,
254    ) -> io::Result<Self> {
255        assert!(bin > 0, "a row has to stand for at least one transaction");
256        let mut out = BufWriter::with_capacity(1 << 20, inner);
257        let placeholder = match format {
258            Format::Pbm => pbm_header(width, 0),
259            Format::Svg => svg_header(width, 0),
260        };
261        out.write_all(placeholder.as_bytes())?;
262        Ok(Writer {
263            out,
264            width,
265            bin,
266            row: vec![0u8; width.div_ceil(8)],
267            dirty: 0,
268            pending: 0,
269            rows: 0,
270            escaped: None,
271            header_len: placeholder.len(),
272            format,
273            pen: None,
274            strokes: Vec::new(),
275            runs: 0,
276            measure: measure || format == Format::Svg,
277        })
278    }
279
280    /// Blacken the pixel for `block` in the row being built.
281    ///
282    /// A block the image has no column for is remembered rather than reported:
283    /// this runs inside the store's walk over the color's terms, which has
284    /// nowhere to put an error.  [`Writer::end_transaction`] raises it, naming
285    /// the first one — the first is the informative one, since the rest are
286    /// whatever the run went on to see afterwards.
287    #[inline]
288    pub fn set(&mut self, block: usize) {
289        if block >= self.width {
290            self.escaped.get_or_insert(block);
291            return;
292        }
293        let byte = block / 8;
294        // Leftmost pixel in the most significant bit, which is P4's order.
295        self.row[byte] |= 0x80 >> (block % 8);
296        if byte >= self.dirty {
297            self.dirty = byte + 1;
298        }
299    }
300
301    /// Finish one transaction, emitting the row if it completes a bin.
302    pub fn end_transaction(&mut self) -> io::Result<()> {
303        if let Some(block) = self.escaped {
304            return Err(io::Error::new(
305                io::ErrorKind::InvalidData,
306                format!(
307                    "block {} has no column in a {}-column picture; \
308                     rerun with --blocks {} or more",
309                    block,
310                    self.width,
311                    block + 1
312                ),
313            ));
314        }
315        self.pending += 1;
316        if self.pending == self.bin {
317            // Nothing is cleared until here, so a bin's transactions have been
318            // drawing into the same row all along: the row is their union
319            // without any of them being asked to compute one.
320            self.flush_row()?;
321        }
322        Ok(())
323    }
324
325    /// Write the row being built and start the next one.
326    fn flush_row(&mut self) -> io::Result<()> {
327        match self.format {
328            Format::Pbm => {
329                self.out.write_all(&self.row)?;
330                if self.measure {
331                    // Nothing here needs the runs; this is only so `--stats` can
332                    // say what the row would have cost drawn the other way.
333                    let runs = &mut self.runs;
334                    for_each_run(&self.row[..self.dirty], |_, _| *runs += 1);
335                }
336            }
337            Format::Svg => {
338                // Split the borrow: the runs come out of `row` while the strokes
339                // go into `strokes`, and both live in `self`.
340                let Writer {
341                    row,
342                    dirty,
343                    strokes,
344                    pen,
345                    rows,
346                    runs,
347                    ..
348                } = self;
349                strokes.clear();
350                for_each_run(&row[..*dirty], |start, length| {
351                    *runs += 1;
352                    match pen.replace((start + length, *rows)) {
353                        // The pen has to be put down somewhere absolute once.
354                        None => {
355                            strokes.push(b'M');
356                            push_int(strokes, start);
357                            strokes.push(b' ');
358                            push_int(strokes, *rows);
359                        }
360                        // Everywhere after that, say how far it moved.  Within a
361                        // row that is the width of the gap; between rows it is a
362                        // long step back and one down, and either way it is far
363                        // fewer digits than saying where it landed.
364                        Some((x, y)) => {
365                            strokes.push(b'm');
366                            push_delta(strokes, start as isize - x as isize);
367                            strokes.push(b' ');
368                            push_delta(strokes, *rows as isize - y as isize);
369                        }
370                    }
371                    strokes.push(b'h');
372                    push_int(strokes, length);
373                });
374                self.out.write_all(&self.strokes)?;
375            }
376        }
377        // Bits are only ever set below `dirty`, so that prefix is the only part
378        // that can be non-zero and the rest is still the zeroes it started as.
379        // Colors are sets of *ancestor* blocks and the chain only grows, so
380        // early rows reach nowhere near the right-hand edge and this is the
381        // difference between clearing the row and clearing the image.
382        self.row[..self.dirty].fill(0);
383        self.dirty = 0;
384        self.pending = 0;
385        self.rows += 1;
386        Ok(())
387    }

389    /// `(columns, rows)` as the header will end up reading, counting the bin in
390    /// progress as the row it is going to become.
391    pub fn dimensions(&self) -> (usize, usize) {
392        (self.width, self.rows + usize::from(self.pending > 0))
393    }
394
395    /// How many runs of adjacent blocks the picture is made of, and what it
396    /// would have cost in each format — the numbers behind the module docs'
397    /// question of which one is smaller.
398    ///
399    /// Only meaningful when the writer was asked to `measure`; the runs of a
400    /// bitmap are not otherwise counted, since nothing about writing one needs
401    /// to know them.
402    pub fn runs(&self) -> (u64, usize, usize) {
403        let per_row = |format: Format| {
404            let (_, rows) = self.dimensions();
405            let mean = if rows == 0 {
406                0
407            } else {
408                (self.runs / rows as u64) as usize
409            };
410            format.row_bytes(self.width, mean)
411        };
412        (self.runs, per_row(Format::Pbm), per_row(Format::Svg))
413    }
414
415    /// Close the picture, stamp the real height into the header, and answer the
416    /// writer it was stamped into.
417    pub fn finish(mut self) -> io::Result<W> {
418        // A bin that never filled up is still a row: the run does not owe the
419        // image a whole bin's worth of transactions at the end of the records.
420        if self.pending > 0 {
421            self.flush_row()?;
422        }
423        if self.format == Format::Svg {
424            self.out.write_all(SVG_TAIL.as_bytes())?;
425        }
426        self.out.flush()?;
427
428        let final_header = match self.format {
429            Format::Pbm => pbm_header(self.width, self.rows),
430            Format::Svg => svg_header(self.width, self.rows),
431        };
432        // The padding exists precisely so this holds; if it ever did not, the
433        // write below would shift the picture by a byte and quietly shear the
434        // whole image, so it is worth saying out loud.
435        assert_eq!(
436            final_header.len(),
437            self.header_len,
438            "the padded header changed length, which would shift the picture"
439        );
440        // Past the buffer rather than through it: the picture has just been
441        // flushed, and a buffered write here would be a write at the end of the
442        // file, not at the front of it.
443        let inner = self.out.get_mut();
444        inner.seek(SeekFrom::Start(0))?;
445        inner.write_all(final_header.as_bytes())?;
446        inner.flush()?;
447        self.out.into_inner().map_err(|e| e.into_error())
448    }
449}

451/// Decimal, straight into the buffer — the driver's [`crate::push_int`], which
452/// exists for the same reason: this runs once per number in a path with tens of
453/// millions of them.
454fn push_int(out: &mut Vec<u8>, value: usize) {
455    crate::push_int(out, value);
456}
457
458/// The same, signed, since every move but the first is a step that can go back
459/// up the row or back to the left of it.
460fn push_delta(out: &mut Vec<u8>, value: isize) {
461    if value < 0 {
462        out.push(b'-');
463    }
464    push_int(out, value.unsigned_abs());
465}

483    fn drawn(
484        format: Format,
485        width: usize,
486        bin: usize,
487        transactions: &[&[usize]],
488    ) -> io::Result<Vec<u8>> {
489        let mut w = Writer::new(Cursor::new(Vec::new()), format, width, bin, true)?;
490        for color in transactions {
491            for &block in *color {
492                w.set(block);
493            }
494            w.end_transaction()?;
495        }
496        Ok(w.finish()?.into_inner())
497    }

499    /// The `d` attribute of the one path in an SVG.
500    fn path_of(image: &[u8]) -> String {
501        let text = std::str::from_utf8(image).unwrap();
502        let start = text.find(" d=\"").unwrap() + 4;
503        text[start..].split('"').next().unwrap().to_string()
504    }
505
506    /// Read a path back into the pixels it draws, so an SVG can be compared with
507    /// the bitmap of the same records.
508    ///
509    /// Only the two commands this writer emits are understood, which is the
510    /// point: it re-derives the picture from the file rather than from anything
511    /// the writer still has in hand.
512    fn rasterize(image: &[u8], width: usize) -> Vec<Vec<bool>> {
513        let mut rows: Vec<Vec<bool>> = Vec::new();
514        let (mut x, mut y) = (0isize, 0isize);
515        let d = path_of(image);
516        let mut tokens = d
517            .replace('M', " M ")
518            .replace('m', " m ")
519            .replace('h', " h ")
520            .split_whitespace()
521            .map(String::from)
522            .collect::<Vec<_>>()
523            .into_iter()
524            .peekable();
525        while let Some(token) = tokens.next() {
526            let mut number = || tokens.next().unwrap().parse::<isize>().unwrap();
527            match token.as_str() {
528                "M" => {
529                    x = number();
530                    y = number();
531                }
532                "m" => {
533                    x += number();
534                    y += number();
535                }
536                "h" => {
537                    let length = number();
538                    while rows.len() <= y as usize {
539                        rows.push(vec![false; width]);
540                    }
541                    for column in x..x + length {
542                        rows[y as usize][column as usize] = true;
543                    }
544                    x += length;
545                }
546                other => panic!("unexpected path command {:?}", other),
547            }
548        }
549        rows
550    }

552    /// The rows of a `P4` image as booleans, for comparing against a path.
553    fn unpack(image: &[u8], width: usize) -> Vec<Vec<bool>> {
554        let (head, raster) = split(image);
555        let rows: usize = std::str::from_utf8(head)
556            .unwrap()
557            .split_whitespace()
558            .nth(2)
559            .unwrap()
560            .parse()
561            .unwrap();
562        let stride = width.div_ceil(8);
563        (0..rows)
564            .map(|r| {
565                (0..width)
566                    .map(|c| raster[r * stride + c / 8] & (0x80 >> (c % 8)) != 0)
567                    .collect()
568            })
569            .collect()
570    }

572    fn split(image: &[u8]) -> (&[u8], &[u8]) {
573        let end = image.iter().position(|&b| b == b'\n').unwrap();
574        let end = image[end + 1..].iter().position(|&b| b == b'\n').unwrap() + end + 2;
575        image.split_at(end)
576    }
