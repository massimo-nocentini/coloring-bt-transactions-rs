1//! # Colors as a picture
2//!
3//! The text output names every block in every color, which on a real run is
4//! tens of gigabytes of `(block . 1)` pairs.  The same answer drawn instead of
5//! spelled: one **row** per transaction, in the order the transactions arrive,
6//! one **column** per block id, counting up from 0, and an inked pixel wherever
7//! that block is in that transaction's color.  A color of a thousand blocks is a
8//! thousand bits rather than fourteen thousand bytes, and how far back a
9//! transaction's coins reach is something you can then look at.
10//!
11//! A pixel carries the coefficient too, which is to say it carries whatever the
12//! backend had to say about the block:
13//!
14//! - unweighted, every coefficient is 1 — the color *is* its set of blocks — so
15//!   a pixel is black where the block is in the color and white where it is not,
16//!   and that is the whole answer.
17//! - under `--weighted` a coefficient is *how much* of the transaction's value
18//!   came through that block, so a pixel is a grey between the two: [`shade`]
19//!   turns the weight into it, black at 1 and white at 0.
20//!
21//! [`Ink`] is which of the two a picture is drawn in, settled when it is opened
22//! because it is the depth of every sample in the file.
23//!
24//! ## A greyscale PNG, one or eight bits a sample
25//!
26//! One channel, and a sample of 0 is black while the largest it can be is white.
27//! At one bit a sample that is [`INK`] and [`PAPER`], the whole of an unweighted
28//! answer, and "the ones in the output" and "the black pixels" stay the same
29//! statement.  At eight it is [`INK`] and [`PAPER_8`] with 254 greys between
30//! them, which is what a weight needs and eight times the file.
31//!
32//! Lossless, and not as a preference.  A pixel here is a whole fact — these
33//! coins did or did not come through that block — so there is no approximation
34//! of one that is still an answer, and at one bit a sample there is nothing to
35//! approximate with in any case.  With PNG that costs nothing to arrange:
36//! deflate is the only compression the format has, and it gives back what it was
37//! given.  `the_picture_round_trips_losslessly` asserts that against a decoder
38//! this file shares no code with, rather than taking the format's word for it.
39//!
40//! ## Why this and not a wavelet codec
41//!
42//! This drew a lossless bilevel JPEG 2000 first, for the reduced resolutions
43//! such a file carries, and what it wrote was a picture almost nothing would
44//! open.  At one bit a sample the codestream says `Ssiz = 0`, and while OpenJPEG
45//! reads that back happily — which is why the round-trip test passed all along —
46//! macOS's ImageIO refuses the file outright, `sips` and Preview with it.
47//! OpenJPEG's own `opj_compress` will not even produce one: hand it a netpbm
48//! with a maxval of 1 and it promotes the samples to eight bits on the way in.
49//! One bit a sample is a corner of that standard the readers did not follow it
50//! into.
51//!
52//! Raising the precision to something they do take costs what the wavelet costs.
53//! The reversible 5/3 filter scales its coefficients with the range of the
54//! samples, so each extra bit of precision is roughly another bitplane for EBCOT
55//! to code — over the paper as much as over the ink, and the paper is most of
56//! it.  On a synthetic run of 42,000 records over 2,000 blocks — 422 pixels in a
57//! thousand inked — the same picture came to
58//!
59//! ```text
60//!     packed raster              10.5 MB
61//!     JPEG 2000, 1 bit a sample   667 kB   and no common reader opens it
62//!     JPEG 2000, 2 bits a sample  2.0 MB
63//!     JPEG 2000, 8 bits a sample  8.2 MB
64//!     this, one bit a sample      309 kB
65//! ```
66//!
67//! so the encoding that could not be read was not the small one either.  A row
68//! here is a stretch of ink and then the white past the block its transaction
69//! was mined in, and a row resembles the row above it; that is the shape LZ77
70//! and Huffman are good at, and they are good at it without spending a bitplane
71//! on the paper.
72//!
73//! What this gives up is the one thing the wavelet was here for.  A JPEG 2000
74//! holds reduced resolutions in the file, so a viewer can show a picture a
75//! hundred thousand rows tall at 1/32 scale without decoding the full size; a
76//! PNG has no such thing, and whatever opens one of these decodes all of it.
77//! That is a real loss, taken deliberately: a picture a viewer can open at one
78//! scale beats a picture it cannot open at six.
79//!
80//! ## Folding transactions together
81//!
82//! A row per transaction is a row per record, and a real run has more records
83//! than any screen has pixels — a million rows is already a picture nothing will
84//! show you whole.  So a row may stand for more than one transaction:
85//! [`Writer::new`]'s `bin` is how many consecutive transactions share a row, and
86//! the row they share is the union of their colors, inked where *any* of them
87//! reaches that block — and, where more than one of them reaches it, inked the
88//! darker of the shades, which is that union again once a pixel is a weight
89//! rather than a bit.  Union is what the driver is computing anyway, so a binned
90//! picture is the same picture at a coarser scale rather than a sampled or
91//! averaged one, and nothing that was inked can go lighter.  The last bin is
92//! whatever is left over, and it is drawn like any other.
93//!
94//! ## Why both dimensions are settled before the first row
95//!
96//! A PNG states its size in `IHDR`, in the twenty-five bytes that come before
97//! the first scanline, so neither number can be discovered along the way.  The
98//! width is the number of blocks and the height is the number of records divided
99//! by the bin, and the driver reads the records once to count both before it
100//! colors any of them — see `main`'s `survey`.  That is why a picture wants an
101//! input it can rewind and a pipe will not do, and why `--blocks <n>`, which
102//! still overrides the width, does not excuse that pass: the height needs it
103//! too.
104//!
105//! `IHDR` does sit at a fixed offset, so a writer willing to seek could stamp
106//! the height in at the end and let the records arrive down a pipe.  This one
107//! does not, and what that would cost is the reason: a height counted in front
108//! of the picture is a height the rows are then *checked against*.
109//! [`Writer::end_transaction`] refuses a row past the last, and
110//! [`Writer::finish`] pads the picture out with blank rows if the records ran
111//! out early — so a run whose two passes disagree is an error rather than a
112//! picture quietly of the wrong shape.
113//!
114//! ## One scanline at a time
115//!
116//! A PNG's pixels are a single deflate stream over the scanlines, each preceded
117//! by the byte naming the filter it was written with, and deflate takes them as
118//! they come.  So a row is packed into the writer's `row` as it is drawn, handed
119//! to the compressor when it closes, and the compressed bytes go out as an
120//! `IDAT` every [`IDAT`] of them.  The working set is one scanline and one
121//! chunk's worth of output — `width / 8 + 1 MiB` bytes, or `width + 1 MiB` for a
122//! weighted picture, however tall the picture — so a drawing far past the size
123//! of memory is still written a megabyte at a time.
124//!
125//! That row buffer holds the scanline itself rather than something to be turned
126//! into one.  Paper is the all-ones byte at either depth — a byte of eight
127//! [`PAPER`] bits, or one [`PAPER_8`] sample — so a row starts as all 1s and
128//! [`Writer::set`] only ever darkens it; the bytes the compressor sees are the
129//! bytes `set` wrote, and nothing is unpacked or copied on the way.
130//!
131//! Every row is filtered with `None`.  PNG's filters predict a byte from its
132//! neighbours, and these rows do resemble the row above — but at one bit a
133//! sample a row is packed eight pixels to the byte, and subtracting one packed
134//! byte from another turns two nearly identical rows into a difference deflate
135//! can no longer match against anything.  On the run above, filtering every row
136//! with `Up` instead came to 402 kB against `None`'s 309 kB.  A weighted row is
137//! a byte a pixel and would take a filter more kindly; it is left on `None` all
138//! the same, so that what a scanline is does not depend on what is in it.
139//!
140//! Nothing here is written twice — unlike the codestream this replaces, which
141//! went back to stamp lengths into markers it had already emitted — so the
142//! output could be any sink the caller has.  It is a path because that is where
143//! the file gets created and nothing has yet wanted otherwise.

145use std::fs::File;
146use std::io::{self, Write};

148use flate2::write::ZlibEncoder;
149use flate2::{Compression, Crc};

151/// A block that is in the color, drawn as fully as the depth allows: 0, black at
152/// either depth.
153pub const INK: u8 = 0;
154
155/// One that is not, at one bit a sample: 1, the largest such a sample can be,
156/// and so white.
157pub const PAPER: u8 = 1;
158
159/// The same at eight bits a sample, where the greys between it and [`INK`] are
160/// what a weight is drawn in.
161pub const PAPER_8: u8 = 255;
162
163/// The exponent that turns a fraction of ink into a shade: `shade =
164/// fraction^(1/TONE)`.
165///
166/// 2.2 is the usual display gamma, chosen here for what it does to the low end
167/// rather than for anything about a monitor — one percent comes out at twelve
168/// percent of the ink, a grey one can see, where one percent black is not.
169pub const TONE: f64 = 2.2;
170
171/// How much ink `fraction` of it comes to, as a byte: 0 is paper and 255 the
172/// full ink.
173///
174/// The two ends are not curved — none is none and all is all, whatever [`TONE`]
175/// is — and in between the curve climbs and never falls, so more ink is always
176/// at least as dark.  What it does *not* say is that twice the darkness is twice
177/// the ink; read a shaded picture for shape, and the text output for quantities.
178///
179/// Both things that shade use this: a weighted *pixel*, whose fraction is the
180/// weight of that block in that color, and a folded *cell*, whose fraction is
181/// how much of the rectangle it covers is inked.  The lift is wanted in both —
182/// weights decay by roughly a factor per hop of ancestry, so most of a real
183/// color is a fraction of a percent and a linear map would draw it as paper.
184pub fn shade(fraction: f64) -> u8 {
185    (fraction.clamp(0.0, 1.0).powf(1.0 / TONE) * 255.0).round() as u8
186}

188/// What a pixel says, which is what the backend behind it had to say about a
189/// block — and, since it is the depth of every sample in the file, something a
190/// picture is opened with rather than told later.
191#[derive(Clone, Copy, PartialEq, Eq)]
192pub enum Ink {
193    /// One bit: the block is in the color or it is not.  Every coefficient of an
194    /// unweighted color is 1, so that is the whole term.
195    Flat,
196    /// Eight bits: how much of the transaction's value came through the block,
197    /// [`shade`]d.
198    Weighted,
199}
200
201impl Ink {
202    /// Bits a sample, which is what `IHDR` is told.
203    fn depth(self) -> u8 {
204        match self {
205            Ink::Flat => 1,
206            Ink::Weighted => 8,
207        }
208    }
209
210    /// Bytes a scanline of `width` pixels comes to, the filter byte aside.
211    fn stride(self, width: usize) -> usize {
212        match self {
213            Ink::Flat => width.div_ceil(8),
214            Ink::Weighted => width,
215        }
216    }
217}

219/// How much compressed output to gather before it goes out as an `IDAT` chunk.
220///
221/// A chunk states its length in front of its data, so this is the one thing held
222/// back at all: the compressor's output has to be in hand before the chunk it
223/// goes in can be started.  It is a working set and nothing else — a PNG is the
224/// same picture however its `IDAT`s are divided up — so the number is a megabyte
225/// for the reason a buffer usually is.
226const IDAT: usize = 1 << 20;
227
228/// The eight bytes every PNG begins with.
229///
230/// The `\x89` and the `\r\n`, `\x1a`, `\n` are the format's own check that
231/// nothing along the way stripped the high bit or rewrote the line endings.
232const SIGNATURE: [u8; 8] = [0x89, b'P', b'N', b'G', 0x0d, 0x0a, 0x1a, 0x0a];
233
234/// The filter byte in front of every scanline.  See the module docs for why it
235/// is always this one.
236const NO_FILTER: u8 = 0;
237
238/// A byte of blank paper: eight [`PAPER`] pixels, or one [`PAPER_8`] sample.
239/// What a row starts as, what a closed row is blanked back to, and what the
240/// slack bits past the last column stay as for the whole picture.
241///
242/// The two depths agree on it, which is why a row is blanked the same way in
243/// both.
244const BLANK: u8 = 0xff;
245
246/// [`Writer::set`] darkens a pixel -- it clears a bit, or lowers a sample --
247/// and a row is blanked back to [`BLANK`], which is paper at either depth only
248/// for as long as these are the three numbers they are.
249const _: () = assert!(INK == 0 && PAPER == 1 && PAPER_8 == BLANK);
250
251/// A picture being drawn a transaction at a time.
252///
253/// A transaction is drawn by [`Writer::set`], once per block in its color, and
254/// closed by [`Writer::end_transaction`]; every `bin` of those makes a row, and
255/// a row that closes goes to the compressor.
256pub struct Writer {
257    /// The file, from the signature to `IEND`, written straight through.
258    out: File,
259    /// The deflate stream the scanlines go into.  Its sink gathers compressed
260    /// bytes until there are [`IDAT`] of them, at which point [`Writer::drain`]
261    /// empties it into a chunk.
262    zip: ZlibEncoder<Vec<u8>>,
263    /// Columns, i.e. how many block ids the picture has room for.
264    width: usize,
265    /// Rows, as promised in `IHDR` before the first scanline.
266    height: usize,
267    /// Transactions to a row.  One is a row each, which is the plain picture.
268    bin: usize,
269    /// What a pixel says, and so how many bits one is.
270    ink: Ink,
271    /// The row being drawn, as the compressor will take it: `row[0]` is
272    /// [`NO_FILTER`] and never changes, and `row[1..]` is the samples as the
273    /// file holds them — packed eight to the byte with the leftmost pixel in the
274    /// most significant bit under [`Ink::Flat`], one byte each under
275    /// [`Ink::Weighted`].  All 1s outside `..dirty` *bytes* of them at all
276    /// times, which is the invariant that lets a closed row be blanked by
277    /// clearing a prefix.
278    row: Vec<u8>,
279    dirty: usize,
280    /// Transactions drawn into the row being built, always below `bin`.
281    pending: usize,
282    /// Rows finished so far, at most `height`.
283    rows: usize,
284    /// The first block id seen that the picture has no column for, if any.
285    escaped: Option<usize>,
286}
287
288impl Writer {
289    /// Open `path` for a picture `width` columns by `height` rows, with `bin`
290    /// transactions to the row and `ink` in its pixels, and write everything up
291    /// to the first scanline.
292    ///
293    /// All of that is final here: see the module docs for why a PNG cannot be
294    /// told its size later, and `IHDR` names the depth in the same breath.
295    pub fn new(path: &str, width: usize, height: usize, bin: usize, ink: Ink) -> io::Result<Self> {
296        assert!(bin > 0, "a row has to stand for at least one transaction");
297        if width == 0 || height == 0 {
298            return Err(io::Error::other(
299                "an image needs a column and a row, and this one has none",
300            ));
301        }
302        // `IHDR` has four bytes for each of them, and a picture that does not
303        // fit in those is not one this format can state the size of at all.
304        if width > u32::MAX as usize || height > u32::MAX as usize {
305            return Err(io::Error::other(format!(
306                "a {} x {} picture is larger than a PNG can say it is",
307                width, height
308            )));
309        }
310
311        let mut out = File::create(path)?;
312        out.write_all(&SIGNATURE)?;
313
314        let mut ihdr = [0u8; 13];
315        ihdr[..4].copy_from_slice(&(width as u32).to_be_bytes());
316        ihdr[4..8].copy_from_slice(&(height as u32).to_be_bytes());
317        ihdr[8] = ink.depth(); // one bit a sample, or eight for a weighted one
318        ihdr[9] = 0; // greyscale: no palette, no colour, no alpha
319        ihdr[10] = 0; // deflate, which is the only compression PNG has
320        ihdr[11] = 0; // the filtering PNG always uses; `NO_FILTER` is per row
321        ihdr[12] = 0; // not interlaced
322        chunk(&mut out, b"IHDR", &ihdr)?;
323
324        let stride = ink.stride(width);
325        let mut row = vec![BLANK; 1 + stride];
326        row[0] = NO_FILTER;
327
328        Ok(Writer {
329            out,
330            zip: ZlibEncoder::new(Vec::with_capacity(IDAT), Compression::best()),
331            width,
332            height,
333            bin,
334            ink,
335            row,
336            dirty: 0,
337            pending: 0,
338            rows: 0,
339            escaped: None,
340        })
341    }
342
343    /// Ink the pixel for `block` in the row being built, with `weight` as its
344    /// coefficient.
345    ///
346    /// The weight is what the term said and nothing else is done to it here:
347    /// under [`Ink::Flat`] it is 1 for every term there is, so the pixel is
348    /// simply black, and under [`Ink::Weighted`] it is the share of the
349    /// transaction's value that came through the block and [`shade`] is the grey
350    /// it comes to.
351    ///
352    /// A pixel a bin has already drawn keeps the darker of the two, which is
353    /// what makes a row the union of its transactions at both depths.
354    ///
355    /// A block the picture has no column for is remembered rather than reported:
356    /// this runs inside the store's walk over the color's terms, which has
357    /// nowhere to put an error.  [`Writer::end_transaction`] raises it, naming
358    /// the first one — the first is the informative one, since the rest are
359    /// whatever the run went on to see afterwards.
360    #[inline]
361    pub fn set(&mut self, block: usize, weight: f64) {
362        if block >= self.width {
363            self.escaped.get_or_insert(block);
364            return;
365        }
366        let byte = match self.ink {
367            Ink::Flat => {
368                let byte = block / 8;
369                // Leftmost pixel in the most significant bit, so that block ids
370                // read left to right across the row -- and cleared rather than
371                // set, because ink is the 0 of the two.  Clearing a bit that is
372                // already clear is the union, at no cost.
373                self.row[1 + byte] &= !(0x80 >> (block % 8));
374                byte
375            }
376            Ink::Weighted => {
377                // A sample counts *up* to white, so the darker of two is the
378                // smaller, and the row keeps that one.
379                let sample = PAPER_8 - shade(weight);
380                let cell = &mut self.row[1 + block];
381                *cell = (*cell).min(sample);
382                block
383            }
384        };
385        if byte >= self.dirty {
386            self.dirty = byte + 1;
387        }
388    }
389
390    /// Finish one transaction, closing the row if it completes a bin.
391    pub fn end_transaction(&mut self) -> io::Result<()> {
392        if let Some(block) = self.escaped {
393            return Err(io::Error::new(
394                io::ErrorKind::InvalidData,
395                format!(
396                    "block {} has no column in a {}-column picture; \
397                     rerun with --blocks {} or more",
398                    block,
399                    self.width,
400                    block + 1
401                ),
402            ));
403        }
404        self.pending += 1;
405        if self.pending == self.bin {
406            // Nothing is blanked until the row closes, so a bin's transactions
407            // have been drawing into the same one all along: the row is their
408            // union without any of them being asked to compute one.
409            self.end_row()?;
410        }
411        Ok(())
412    }
413
414    /// Hand the row being built to the compressor, blank it, and start the next.
415    fn end_row(&mut self) -> io::Result<()> {
416        if self.rows == self.height {
417            return Err(io::Error::new(
418                io::ErrorKind::InvalidData,
419                format!(
420                    "the picture was opened {} rows tall and the records have filled it; \
421                     the count they were measured by is not the count they are arriving at",
422                    self.height
423                ),
424            ));
425        }
426        self.zip.write_all(&self.row)?;
427        // Samples are only ever darkened below `dirty`, so that prefix is the
428        // only part of the row that can have gone dark and the rest is still the
429        // paper it started as.  Colors are sets of *ancestor* blocks and the
430        // chain only grows, so early rows reach nowhere near the right-hand edge
431        // and this is the difference between blanking a prefix and blanking the
432        // width.
433        self.row[1..1 + self.dirty].fill(BLANK);
434        self.dirty = 0;
435        self.pending = 0;
436        self.rows += 1;
437        self.drain()
438    }
439
440    /// Send what the compressor has produced, if there is a chunk's worth of it.
441    ///
442    /// A chunk needs its length in front of it, which is what holds any of the
443    /// output back at all; the tail below [`IDAT`] is left for
444    /// [`Writer::finish`], which has the end of the deflate stream to add to it
445    /// anyway.
446    fn drain(&mut self) -> io::Result<()> {
447        if self.zip.get_ref().len() < IDAT {
448            return Ok(());
449        }
450        chunk(&mut self.out, b"IDAT", self.zip.get_ref())?;
451        // Emptied rather than replaced: the capacity is the buffer.
452        self.zip.get_mut().clear();
453        Ok(())
454    }
455
456    /// `(columns, rows)` as the picture was opened for, which is what it will be
457    /// however many records turn up.
458    pub fn dimensions(&self) -> (usize, usize) {
459        (self.width, self.height)
460    }
461
462    /// Close the picture: finish the row in hand, pad out to the promised
463    /// height, end the deflate stream and write `IEND`.
464    pub fn finish(mut self) -> io::Result<()> {
465        // A bin that never filled up is still a row: the run does not owe the
466        // picture a whole bin's worth of transactions at the end of the records.
467        if self.pending > 0 {
468            self.end_row()?;
469        }
470        // The height went into `IHDR` before the first scanline, so the picture
471        // owes exactly that many rows.  Short of them the file is a truncated
472        // image every reader complains about; blank rows are at least an honest
473        // picture of records that were not there.
474        while self.rows < self.height {
475            self.end_row()?;
476        }
477        // Ending the stream puts deflate's last block and its checksum into the
478        // same buffer, on top of the tail the last `drain` left in it, and hands
479        // the buffer back.  A zlib stream always ends with something, so this is
480        // never the empty chunk the check below would otherwise be about; the
481        // check is there because a chunk of nothing is not worth writing.
482        let held = self.zip.finish()?;
483        if !held.is_empty() {
484            chunk(&mut self.out, b"IDAT", &held)?;
485        }
486        chunk(&mut self.out, b"IEND", &[])?;
487        self.out.flush()
488    }
489}
490
491/// One PNG chunk: its length, its four-byte name, its data, and a CRC-32 over
492/// the name and the data — the length deliberately not among them, since it is
493/// what a reader has to trust before it can check anything.
494fn chunk(out: &mut File, name: &[u8; 4], data: &[u8]) -> io::Result<()> {
495    debug_assert!(
496        data.len() <= u32::MAX as usize,
497        "a chunk states its length in four bytes"
498    );
499    let mut head = [0u8; 8];
500    head[..4].copy_from_slice(&(data.len() as u32).to_be_bytes());
501    head[4..].copy_from_slice(name);
502    out.write_all(&head)?;
503    out.write_all(data)?;
504
505    let mut crc = Crc::new();
506    crc.update(name);
507    crc.update(data);
508    out.write_all(&crc.sum().to_be_bytes())
509}

515    /// A path under the test runner's temporary directory, distinct per test so
516    /// that the tests can run in the same directory at the same time.
517    fn scratch(name: &str) -> String {
518        std::env::temp_dir()
519            .join(format!("colors-{}-{name}.png", std::process::id()))
520            .to_string_lossy()
521            .into_owned()
522    }
523
524    /// The picture at `path`, read back with a decoder this file shares no code
525    /// with: its size and its samples, row-major, a byte a pixel — and its depth
526    /// checked against the `ink` it was drawn in.
527    ///
528    /// The bits are unpacked here rather than by asking the decoder to expand
529    /// them, so that a sample of [`INK`] means what this file says it means and
530    /// the decoder is left to do the inflating and the unfiltering — the two
531    /// steps a writer cannot check itself.
532    fn decode(path: &str, ink: Ink) -> (usize, usize, Vec<u8>) {
533        let file = io::BufReader::new(File::open(path).unwrap());
534        let mut reader = png::Decoder::new(file).read_info().expect("a PNG header");
535        {
536            let info = reader.info();
537            let depth = match ink {
538                Ink::Flat => png::BitDepth::One,
539                Ink::Weighted => png::BitDepth::Eight,
540            };
541            assert_eq!(info.bit_depth, depth, "the depth the picture was drawn at");
542            assert_eq!(
543                info.color_type,
544                png::ColorType::Grayscale,
545                "one greyscale channel"
546            );
547        }
548        let mut buf = vec![0u8; reader.output_buffer_size().unwrap()];
549        let frame = reader.next_frame(&mut buf).unwrap();
550        let (w, h) = (frame.width as usize, frame.height as usize);
551        let mut samples = Vec::with_capacity(w * h);
552        for y in 0..h {
553            let row = &buf[y * frame.line_size..(y + 1) * frame.line_size];
554            for x in 0..w {
555                samples.push(match ink {
556                    Ink::Flat => (row[x / 8] >> (7 - x % 8)) & 1,
557                    Ink::Weighted => row[x],
558                });
559            }
560        }
561        (w, h, samples)
562    }

565    /// decodes back to, as `#` for ink and `.` for paper.
566    fn draw(name: &str, width: usize, rows: usize, colors: &[&[usize]]) -> Vec<String> {

570    /// The same, with `bin` transactions to the row.
571    fn binned(
572        name: &str,
573        width: usize,
574        rows: usize,
575        bin: usize,
576        colors: &[&[usize]],
577    ) -> Vec<String> {
578        let path = scratch(name);
579        write(&path, width, rows, bin, colors).unwrap();
580        let picture = rendered(&path, width, rows);
581        std::fs::remove_file(&path).ok();
582        picture
583    }

585    /// Draw `colors` -- a `(block, weight)` a term, `bin` transactions to a row
586    /// -- as a weighted picture, and answer its samples row-major.
587    fn weighted(
588        name: &str,
589        width: usize,
590        rows: usize,
591        bin: usize,
592        colors: &[&[(usize, f64)]],
593    ) -> Vec<Vec<u8>> {
594        let path = scratch(name);
595        {
596            let mut w = Writer::new(&path, width, rows, bin, Ink::Weighted).unwrap();
597            for color in colors {
598                for &(block, weight) in *color {
599                    w.set(block, weight);
600                }
601                w.end_transaction().unwrap();
602            }
603            w.finish().unwrap();
604        }
605        let (cols, got, samples) = decode(&path, Ink::Weighted);
606        assert_eq!((cols, got), (width, rows), "the size it was opened for");
607        std::fs::remove_file(&path).ok();
608        samples.chunks(width).map(|row| row.to_vec()).collect()
609    }

611    /// Draw the colors into a file, leaving whatever error came of it to the
612    /// caller — the tests that expect one need the writer's own message.
613    fn write(
614        path: &str,
615        width: usize,
616        rows: usize,
617        bin: usize,
618        colors: &[&[usize]],
619    ) -> io::Result<()> {
620        let mut w = Writer::new(path, width, rows, bin, Ink::Flat)?;
621        for color in colors {
622            for &block in *color {
623                w.set(block, 1.0);
624            }
625            w.end_transaction()?;
626        }
627        w.finish()
628    }

630    /// The decoded file as one string a row, checked against the size it was
631    /// asked for.
632    fn rendered(path: &str, width: usize, rows: usize) -> Vec<String> {
633        let (w, h, samples) = decode(path, Ink::Flat);
634        assert_eq!((w, h), (width, rows), "the size the picture was opened for");
635        samples
636            .chunks(width)
637            .map(|row| {
638                row.iter()
639                    .map(|&s| if s == INK { '#' } else { '.' })
640                    .collect()
641            })
642            .collect()
643    }

833    /// black, none of it is paper, and the greys in between order the way the
834    /// weights do.
