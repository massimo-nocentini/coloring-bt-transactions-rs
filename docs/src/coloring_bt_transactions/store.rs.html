1//! # What the driver needs a color to be
2//!
3//! [`crate::poly`] is a port of a Knuth exercise and the circular list is its
4//! whole subject, so it stays exactly as it is.  But the *driver* does not
5//! actually need polynomials.  It needs sets of block ids: every coefficient it
6//! ever handles is 1, and `ior` on 1s is 1, so a color is a set and `ior` is
7//! union — `main` says as much in its own docs.
8//!
9//! That gap is worth something.  A set of small integers can live in a flat
10//! sorted array, where a union is a sequential scan of two runs of `u32` rather
11//! than a chase down two chains of 24-byte nodes, and where a vector unit has
12//! something to work on.  A ring cannot be walked that way: the merge in
13//! [`crate::poly::Arena::op`] loads `next` to find out where to load next, so it
14//! is latency-bound, and no vector instruction shortens a dependent load.
15//!
16//! So there are two implementations, and this trait is the line between them:
17//!
18//! - [`RingStore`] — the exercise, wrapping [`crate::poly::Arena`] untouched.
19//! - [`crate::colorset::SetStore`] — sorted arrays, for speed.
20//!
21//! Keeping both is not sentiment.  The driver is deterministic and its output is
22//! byte for byte comparable, so running the same records through both backends
23//! and diffing is an equivalence check between two implementations that share no
24//! code — a stronger statement about the fast one than any test it could be
25//! given on its own.
26//!
27//! ## Why the trait is shaped this way
28//!
29//! [`ColorStore::combine`] takes its operands **by reference** and neither is
30//! consumed, which is already [`crate::poly::Arena::op`]'s contract.  What the
31//! driver must be explicit about instead is wanting a *second handle* on a
32//! color, [`ColorStore::share`], because that is a ring copy for one backend and
33//! a refcount bump for the other — the whole difference between them, in one
34//! method.
35//!
36//! Nothing here is dyn-safe, on purpose: `run` is generic over this trait and
37//! instantiated once per backend, so the calls compile to what they would if the
38//! backend were named directly.
39
40use crate::poly::{Arena, Idx};
41
42/// A place colors live, and everything the driver does to them.
43///
44/// A [`ColorStore::Color`] is a handle whose meaning is private to the store
45/// that made it; handing one to a different store is a bug this trait cannot
46/// prevent.  Handles are owned — [`ColorStore::release`] each exactly once —
47/// which is why `Color` is deliberately not `Copy`.
48pub trait ColorStore {
49    type Color;
50
51    /// Whether [`ColorStore::combine`] and [`ColorStore::scale`] do anything
52    /// with the weights they are handed.
53    ///
54    /// A constant rather than a method so the driver can skip working the
55    /// weights out at all for stores that ignore them: `run` is instantiated per
56    /// backend, so `if S::WEIGHTED` folds away at compile time and the
57    /// unweighted path costs exactly what it did before weights existed.
58    const WEIGHTED: bool;
59
60    fn new() -> Self;
61
62    /// The color of a coinbase transaction: the one block that minted it, with
63    /// all of the weight on it.
64    fn singleton(&mut self, block: usize) -> Self::Color;
65
66    /// `wa * a + wb * b`: union of the two supports, with the weights of each
67    /// side scaled on the way through and matching blocks summed.
68    ///
69    /// Borrows both operands and leaves them untouched.  Stores with
70    /// [`ColorStore::WEIGHTED`] false ignore `wa` and `wb` and answer the plain
71    /// union, which is the same thing when every weight is 1 and the driver only
72    /// ever asks for `ior`.
73    fn combine(&mut self, a: &Self::Color, wa: f64, b: &Self::Color, wb: f64) -> Self::Color;
74
75    /// Every weight multiplied by `w`.  Ignored, and equivalent to
76    /// [`ColorStore::share`], when [`ColorStore::WEIGHTED`] is false.
77    fn scale(&mut self, color: &Self::Color, w: f64) -> Self::Color;
78
79    /// A second owned handle on the same color.  A copy for [`RingStore`], a
80    /// refcount bump for a sharing store; callers should assume it is expensive.
81    fn share(&mut self, color: &Self::Color) -> Self::Color;
82
83    /// Give a handle back.  It must not be used again.
84    fn release(&mut self, color: Self::Color);
85
86    /// Visit the blocks in decreasing order as `(exponent, coefficient)` pairs.
87    ///
88    /// The coefficient is an `f64` whichever store this is.  For the unweighted
89    /// ones it is always exactly `1.0` and the driver prints it as the integer
90    /// the Scheme prints; carrying it as a float costs nothing there and saves
91    /// the trait an associated type that only one backend would use.
92    fn for_each_term(&self, color: &Self::Color, f: impl FnMut(usize, f64));
93
94    /// Offered each finished color, so a store with an invariant can watch it.
95    ///
96    /// Only called under `--stats`, because checking one generally means a pass
97    /// over the color and that is not worth doing on every record of a real run.
98    /// The default does nothing.
99    fn observe(&mut self, _color: &Self::Color) {}
100
101    /// `(live, committed)` in whatever unit the store counts, for `--stats`,
102    /// with [`ColorStore::usage_labels`] naming them.  The backends count
103    /// different things, so these compare across a run, not across backends.
104    fn usage(&self) -> (usize, usize);
105
106    fn usage_labels(&self) -> (&'static str, &'static str);
107
108    /// One line saying whether everything the store thinks is live is reachable
109    /// from the colors the driver still holds.  A leak is invisible in the
110    /// output — a leaked color is still a *correct* color — so it needs its own
111    /// check.
112    fn audit(&self, live: &mut dyn Iterator<Item = &Self::Color>) -> String;
113}
114
115/// The circular-list backend: [`crate::poly::Arena`] plus the one thing the
116/// arena has no room for, a shared empty ring to copy against.
117///
118/// The empty ring is what the driver used to call `zero` and use as its fold
119/// seed.  The fold no longer needs a seed, but [`ColorStore::share`] does need
120/// something to merge against in order to produce a copy, and allocating a fresh
121/// empty ring per call would be silly.  It is one node, which is exactly what
122/// `zero` cost before, so `--stats` reads the same as it always did.
123pub struct RingStore {
124    arena: Arena,
125    empty: Idx,
126}
127
128impl ColorStore for RingStore {
129    type Color = Idx;
130
131    /// The exercise's `ior` has no room for a weight: `poly::op` copies a
132    /// coefficient straight across whenever only one side carries the term, so a
133    /// weight would reach the shared blocks and miss all the others.  Saying so
134    /// here is what keeps the driver from computing weights this backend would
135    /// quietly drop.
136    const WEIGHTED: bool = false;
137
138    fn new() -> Self {
139        let mut arena = Arena::new();
140        let empty = arena.make(&[]);
141        RingStore { arena, empty }
142    }
143
144    fn singleton(&mut self, block: usize) -> Idx {
145        self.arena.make(&[(block, 1)])
146    }
147
148    fn combine(&mut self, a: &Idx, _wa: f64, b: &Idx, _wb: f64) -> Idx {
149        self.arena.ior(*a, *b)
150    }
151
152    fn scale(&mut self, color: &Idx, _w: f64) -> Idx {
153        self.share(color)
154    }
155
156    fn share(&mut self, color: &Idx) -> Idx {
157        // No refcount to bump, so a second handle is a second ring.  Union with
158        // the empty ring is the identity, so it is also a term-for-term copy.
159        self.arena.ior(*color, self.empty)
160    }
161
162    fn release(&mut self, color: Idx) {
163        self.arena.free_ring(color);
164    }
165
166    fn for_each_term(&self, color: &Idx, mut f: impl FnMut(usize, f64)) {
167        // `poly` counts in integers and always hands back 1 here, since the
168        // driver only ever asks it for `ior`.  The widening is exact.
169        self.arena
170            .for_each_term(*color, |exponent, coefficient| {
171                f(exponent, coefficient as f64)
172            });
173    }
174
175    fn usage(&self) -> (usize, usize) {
176        (self.arena.live(), self.arena.capacity())
177    }
178
179    fn usage_labels(&self) -> (&'static str, &'static str) {
180        ("live nodes", "arena nodes")
181    }
182
183    fn audit(&self, live: &mut dyn Iterator<Item = &Idx>) -> String {
184        let reachable: usize = self.arena.ring_len(self.empty)
185            + live.map(|&root| self.arena.ring_len(root)).sum::<usize>();
186        let held = self.arena.live();
187        if reachable == held {
188            format!("audit: {} live nodes, all reachable", held)
189        } else {
190            format!(
191                "audit: LEAK -- {} live nodes but only {} reachable ({} lost)",
192                held,
193                reachable,
194                held - reachable
195            )
196        }
197    }
198}
